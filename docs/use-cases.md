# Use cases

## UC-01. Создание адресата

**Актор:** Оператор.  
**Предусловие:** адресат с таким реестровым номером отсутствует.  
**Результат:** создана запись Citizen и Address.

## UC-02. Создание повестки

**Актор:** Оператор.  
**Предусловие:** существуют адресат и подразделение.  
**Основной поток:** оператор задает номер, даты, причину и комментарий → система валидирует данные → сохраняет повестку → создает начальную запись истории статусов → пишет audit event.

## UC-03. Просмотр реестра

**Актор:** Оператор/Руководитель/Наблюдатель.  
**Результат:** таблица повесток с фильтрацией по статусу, подразделению и строке поиска.

## UC-04. Просмотр карточки повестки

Показываются адресат, подразделение, дата выпуска, срок, текущий статус, история статусов, уведомления и обращения.

## UC-05. Изменение статуса

**Актор:** Оператор.  
**Правило:** переход фиксируется в SummonsStatusHistory и AuditEvent.

## UC-06. Отправка mock-уведомления

Оператор выбирает канал. Система создает Notification и DeliveryAttempt со статусом `Delivered` для демонстрационной среды.

## UC-07. Регистрация обращения

Оператор фиксирует тип обращения и текст. Обращение привязывается к повестке и получает статус `Submitted`.

## UC-08. Добавление документа

Сохраняются метаданные документа: имя, MIME type, URI/идентификатор хранилища. В MVP бинарный файл не принимается.

## UC-09. Просмотр истории

Руководитель видит последовательность изменений статусов и аудит действий.

## UC-10. Проверка работоспособности

DevOps/преподаватель запускает `docker compose up --build` и открывает UI, API и Swagger.
