# Реестр повесток ЦИПСО

**ЦИПСО** — **«Централизованная информационная платформа списков оповещения»**.

Учебное клиент-серверное веб-приложение для учёта **электронных повесток военного учёта**, статусов оповещения, истории повесток, обращений и сопроводительных документов призывного учёта.

> Проект демонстрационный, не связан с государственными информационными системами и использует только сгенерированные данные.

## Предметная область

Система моделирует работу военно-учётного стола:

- **Секретарь** (`Operator`) — создаёт призывников и повестки, меняет статусы, регистрирует обращения и mock-уведомления;
- **Комиссар** (`Manager`) — имеет права чтения/изменения и просматривает историю и аудит;
- **Призывник** (`Observer`) — просматривает данные и предусмотренные документы;
- **Инженер автоматизации военно-учётного стола** (`AutomationEngineer`) — создаёт и удаляет системные учётные записи.

Основные объекты: призывник, адрес регистрации, военкомат, сотрудник, повестка, история статусов, уведомление, попытка доставки, обращение, документ, аудит и системная учётная запись.

## Аутентификация

По проектному ТЗ пользователь **не вводит локальный логин и пароль**.

Предусмотрены внешние способы входа:

- MAX;
- Госуслуги с использованием «Госключа».

Реальной интеграции с этими внешними системами в учебном проекте пока нет. На экране входа находятся **две явно обозначенные заглушки**, которые имитируют успешную внешнюю аутентификацию для заранее созданных учебных учётных записей. После mock-входа backend выдаёт обычный JWT Bearer.

Самостоятельная регистрация отсутствует. Новые учётные записи создаются инженером автоматизации в разделе `/accounts`.

## Реализовано

- реестр повесток военного учёта;
- 25 синтетических повесток для демонстрации пагинации;
- карточки 12 синтетических призывников;
- 2 учебных военкомата;
- создание повестки с выбором призывника и военкомата;
- срок явки и причина явки;
- история статусов;
- mock-уведомления и попытки доставки;
- обращения призывников;
- метаданные документов призывного учёта;
- аудит действий;
- role-based authorization;
- mock-вход через MAX / Госуслуги;
- служебное создание учётных записей инженером автоматизации;
- серверные фильтры и пагинация;
- EF Core migrations;
- CI frontend/backend.

## Запуск

```bash
cp .env.example .env
docker compose up --build
```

Адреса:

- UI: http://localhost:8080
- API: http://localhost:8081
- Swagger: http://localhost:8081/swagger
- Health: http://localhost:8081/api/health

При обновлении старой учебной БД backend автоматически регистрирует initial migration, если схема ранее была создана через `EnsureCreated`.

## Демо-вход

На странице входа выберите одну из заранее созданных ролей:

- Демо-секретарь;
- Демо-комиссар;
- Демо-призывник;
- Демо-инженер автоматизации.

После выбора нажмите **«Войти через MAX»** либо **«Войти через Госуслуги»**. Обе кнопки пока являются заглушками и не обращаются к реальным внешним сервисам.

## Маршруты UI

- `/login` — внешний вход (заглушки);
- `/dashboard` — сводка;
- `/summons` — реестр повесток;
- `/summons/new` — создание повестки;
- `/summons/:id` — карточка повестки;
- `/citizens` — призывники;
- `/appeals` — обращения;
- `/documents` — документы;
- `/accounts` — учётные записи (Automation Engineer).

## Ограничения учебной версии

- MAX и Госуслуги/«Госключ» не интегрированы — используются только заглушки;
- реальная отправка SMS/e-mail отсутствует;
- бинарные документы не загружаются, хранятся только метаданные;
- используются только сгенерированные персональные данные;
- JWT key предназначен исключительно для локальной демонстрации.
